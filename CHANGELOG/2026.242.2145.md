# 2026.242.2145 — feat(file): link_target — assert where a symlink points, not just that it is one

## Summary

`filetype: symlink` proves a path IS a link and says nothing about where it points, and for
a whole class of assertions where it points is the entire claim:

| path | what its target means |
|---|---|
| `/etc/localtime` | the configured timezone |
| `/usr/bin/<x>` | which alternative is in use |
| `/etc/systemd/system/*.wants/*` | which unit is enabled |

Without this the only recourse is `command: readlink`, which forfeits the exists / mode /
owner / filetype assertions the same step could otherwise make about the link itself.

The target is **fully resolved** (`readlink -f`), so a relative link such as
`../usr/share/zoneinfo/UTC` is asserted as `/usr/share/zoneinfo/UTC` and a chain is followed
to its end. That is the question these assertions actually ask — "what does this resolve
to" — and it is stable across distros that spell the same answer differently.

It takes the same matcher list as `contains:`, so `equals`, `contains` and `matches` all
work on the target.

## Two ways this could have failed open, both closed

**A non-symlink FAILS rather than self-matching.** `readlink -f /etc/hosts` prints
`/etc/hosts` for a regular file, so `link_target: /etc/hosts` on a regular file would
otherwise pass while asserting precisely nothing.

**A dangling link FAILS rather than matching an empty string.** An empty subject satisfies
every `not_contains:` matcher, so returning it would turn "this link does not point at the
wrong place" into an unconditional pass on exactly the broken systems the check exists for.

## A silent-failure class, found and then guarded

`fileCheck` is a **hand-written projection** of `params.FileInput`, built by a struct literal
in `RunVerb`. A field added to the CUE schema flows into `params.FileInput` automatically
when the generator runs — and then reaches **nothing**, because the literal does not copy it.
Everything compiles, `charly box validate` accepts the authored step, and the check silently
ignores the field and passes.

That is not hypothetical: it happened while writing this. Schema, generated params type and
probe were all correct and `link_target` was still invisible until the literal was updated.

`projection_parity_test.go` walks `params.FileInput` by reflection and requires a same-named
field on `fileCheck` (with one declared rename: the primary `File` → `Path`), plus the
mirror direction — a `fileCheck` field no input can fill is a value the probe branches on
that nothing can ever set. It carries a field-count floor so a reflection that stops seeing
the type fails instead of passing vacuously.

Negative control, on the TRUE silent case — field present in params, projected nowhere, and
referenced by no probe, so it still **compiles**:

```
--- FAIL: TestFileCheckProjectsEveryInputField
    params.FileInput.LinkTarget has no LinkTarget on fileCheck: the field is decoded
    from the step and then DROPPED, so an authored `linktarget:` silently asserts nothing
```
